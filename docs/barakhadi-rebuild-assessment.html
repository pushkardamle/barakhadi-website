Payment prototype

Cloudflare Worker "barakhadi-subscription", deployed 14 Dec 2025, recovered today

Your memory was close: the pages are plain HTML, CSS and JS. The backend is a ~550-line Cloudflare Worker in old service-worker syntax that calls the Stripe and TalentLMS v1 APIs directly with fetch. This is how it worked:

  1. subscribe.html

    The parent enters an email, password, the student's name, age group, level (0/1/2), a parent name if the student is under 18, ticks reCAPTCHA v2, and agrees to terms (those pages don't exist).

  2. Worker · /api/check-email

    When the email field loses focus, the Worker downloads your entire TalentLMS user list and checks whether the email is taken. Anyone could use it to test emails, and it slows down as you grow.

  3. Worker · /api/create-checkout-session

    Creates a Stripe Checkout session: $60 USD one-time "Barakhadi Annual Subscription", with all form fields in metadata, including the plain-text password. The reCAPTCHA token is sent but never verified.

  4. Stripe → Worker · /api/stripe-webhook

    On checkout.session.completed: no signature check. Then usersignup (user type "Student-Independent", branch 14) → addusertogroup with that level's group key → edituser deactivation date +364 days. If the group step fails, it deletes the user.

  5. thank-you.html · /api/verify-enrollment

    Waits 5 seconds, polls up to 3 times for the user in TalentLMS, then shows success regardless. Failed enrollments were only written to logs. No alert was sent.

Ideas worth keeping

  • One TalentLMS group per level, so enrolling in a group enrolls the student in all that level's courses.
  • A deactivation date for the end of access. Deactivated users keep their progress and stop using a seat.
  • A dedicated "Student-Independent" user type and branch for paying families.
  • Rolling back the user if enrollment fails.

What the rebuild must change

  • Verify Stripe signatures, store each event once in a database (D1), and process it from a queue that retries and alerts on failure.
  • Never collect passwords. Use a TalentLMS password-set email or a one-click login link instead.
  • Use TalentLMS API v2 (v1 is deprecated), with the key kept as an encrypted secret.
  • Support real subscriptions with renewals, trials, one-time courses and school seats, plus Stripe's Customer Portal so customers can manage them.
  • Show the real status on the thank-you page, and look users up by email instead of downloading everyone.

A · Astro 7 on Cloudflare Workers

Recommended

Pages are pre-built HTML from Markdown and .astro components, served from Cloudflare's edge. The same project includes server endpoints for checkout, the Stripe webhook and forms, with Cloudflare D1 (database), Queues (retries), Cron (nightly checks) and Turnstile (spam protection). Cloudflare acquired the Astro team in January 2026, and the Astro Cloudflare adapter now targets Workers rather than Pages.

Pros

  • Cheapest and lowest-maintenance code option, with no server to patch.
  • Best page speed of the three, which helps SEO and ads.
  • Files in Git, so every Claude change is a reviewable diff, with a preview URL per branch.
  • One platform for the site, payments, background jobs and DNS.
  • The same setup as your other two sites, so the tooling and habits carry over.

Cons

  • Astro 7 is only 4 months old, so some AI-generated code may target Astro 5/6 patterns. A CLAUDE.md file and the docs MCP server mitigate this.
  • Rich app-like dashboards are less natural than in Next.js. Islands cover what we need.
  • Cloudflare-specific pieces (D1, Queues) tie the backend to Cloudflare.
  • Still needs a monthly dependency update. Astro had a few security advisories in 2026.

B · Next.js 16 (Vercel, or Cloudflare via OpenNext)

Strong for apps, heavy for a 4-page site

The React full-stack framework with the most tutorials and the most AI training data. It would be the pick if Barakhadi turned into a large logged-in web app.

Pros

  • The most examples for Stripe, auth and dashboards.
  • Excellent SEO tooling and preview deploys.
  • The best path if teacher and school dashboards become the main product.

Cons

  • A high security-patch cadence in 2025–26, including several critical remote-code-execution bugs.
  • Vercel costs $20/mo or more for commercial use. OpenNext on Cloudflare needs WSL on Windows and a paid plan for bundle size.
  • More concepts to learn (server and client components, caching), and it ships more JS to every page.

C · WordPress + Bricks Builder on Cloudways

The minimum change

Swap Elementor for Bricks and keep WordPress and Cloudways. You know this world, but it keeps the exact problems you want to leave.

Pros

  • A familiar visual editor, with no code needed for page edits.
  • A huge plugin ecosystem (SEO, forms, memberships).
  • No DNS or hosting migration.

Cons

  • Constant updates and security exposure: 11,334 new WordPress-ecosystem vulnerabilities in 2025, 91% of them in plugins.
  • Content lives in MySQL, which makes AI edits risky and impossible to review.
  • Subscriptions need paid plugins, or you keep a separate Worker anyway.
  • The highest ongoing cost of the three.
Also considered and set aside
  • Plain HTML + a Worker (what the prototype was): zero dependencies, but you hand-build layouts, the blog, sitemaps, image optimization and i18n. Astro outputs the same static HTML and does those for you.
  • SvelteKit: excellent on Cloudflare, but version 3 is still a release candidate and its main new feature is experimental.
  • Webflow or Framer: visual-editor-first, per-site fees, not Git or AI friendly, and you'd still need a Worker for the Stripe → TalentLMS step.
  • Headless WordPress: keeps WordPress to patch and adds a separate frontend. The worst of both.

Recommended plan

Option A, in four phases on one codebase
Phase 1 · first

Replace WordPress

  • New repo in barakhadi-web (private GitHub) with Astro 7 + Tailwind 4 and the redesign's design system, fixed for contrast and with a mobile menu.
  • Pages: Home, FAQ (/faq/), Contact (/contact-us/), How it works (videos), Privacy, Terms.
  • Free-trial links and Login go to TalentLMS as they do today. No payments yet.
  • Contact form with Turnstile, sending email through Resend.
  • SEO basics, Cloudflare Web Analytics, a noindex staging URL.
  • Move DNS from Namecheap to Cloudflare, add email routing, 301/410 redirects, then cancel Cloudways.
Phase 2

Sell on barakhadi.com

  • Stripe products: family subscription (monthly or annual, with a trial), one-time course, school seats priced per seat.
  • Verified webhook → D1 → Queue → TalentLMS v2: create the user, add them to the level group, activate or deactivate.
  • No password at checkout. Welcome email with a login link.
  • Stripe Customer Portal for cards, renewals and cancellations.
  • Alert emails and a nightly reconciliation.
Phase 3

Learn on your domain

  • Point learn.barakhadi.com at TalentLMS with a CNAME, and brand the portal.
  • "Go to my lessons" button using TalentLMS one-time login links.
  • Catalog pages generated from TalentLMS course data.
Phase 4 · later

Accounts and teacher area

  • Parent and teacher accounts on barakhadi.com (Better Auth + D1).
  • Optional single sign-on into TalentLMS, with barakhadi.com as the identity provider.
  • Teacher and school dashboard: class rosters, progress and assignments from API v2, cached.
  • Schools manage their purchased seats themselves.
  • Revisit the TalentLMS plan if Group Supervisor or more branches would replace custom work.

Expected running cost after Phase 2: $0–5/month for Cloudflare, about $10/year for the domain, and Stripe fees (about 2.9% + 30¢ per card payment, plus 0.7% Billing for subscriptions, plus 0.5% if you use Stripe Tax). Resend's free tier covers 3,000 emails/month.
