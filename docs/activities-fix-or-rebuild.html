Barakhadi Activities: Fix or Rebuild

Why the activities show scrollbars, a fix that costs almost nothing, and whether it's worth rebuilding the Storyline activities in modern HTML5 with AI.

Prepared 18 Oct 2026 for Pushkar · based on inspecting the live free activity "Sem. 1 - Week 1 - Conversation" and current TalentLMS and Articulate documentation.

क

Short answer

Both questions

Scrollbars: not a TalentLMS limitation. The activities were published from Storyline with the player locked at 960×640, so they can't shrink to fit TalentLMS's frame (about 890×540 on a typical laptop). Changing one line in each published package makes them scale to any screen. No Storyline licence needed.

Rebuild: worth it, but not as one big rewrite. The current files are Storyline 3 from 2017. They still work on desktop, but their tablet handling points to an app that no longer exists, and they're hard to change. Rebuild gradually, starting with the new self-learner (indml) course copies you already plan to make. Do a small pilot first to measure the real effort. AI can build the activity engines and handle most of the content conversion. The slow part is checking every activity by hand.

Fixing the scrollbars

Three options, cheapest first

A · Patch the published packages

Recommended now

Change two lines in each package, then re-zip:

story_html5.html:  scale: 'noscale'  →  scale: 'show all'
story.html:        remove the "amp" (mobile app) entry
                   from runtimeOrder, so tablets go
                   straight to the HTML5 player

This can be scripted for every package in a few minutes. It needs the published package zips, either your originals or downloads from TalentLMS. Then replace each unit's file in TalentLMS.

B · TalentLMS unit settings

Partial

xAPI/SCORM units have Show as: Embedded or Pop-up and a Size (width × height) setting. Pop-up at 980×680 would show the activity without scrollbars, but in a separate window. That's clumsy for kids, and it doesn't fix tablets. Useful as a stopgap if you can't get the packages.

C · Republish in Storyline 360

Costly

Open each .story file in Storyline 360 and republish with "Scale player to fill browser". You get the modern responsive player. It needs the source files and an Articulate 360 subscription (about $1,449 a year), and it's manual work for every activity. Storyline 3 files still upgrade automatically. Turn on "Modern Text", because Storyline has had Devanagari vowel-sign bugs.

Before rolling out A: test it on one activity in a copy of a course. Replacing a unit's file may reset that unit's learner records (unverified), so check before touching courses that students are using. Test on a laptop, an iPad and a phone.

The 50% / 66% progress: this is caused by the assignment unit, not the activity format. An assignment set to complete "When the instructor accepts the answer" stays pending until someone grades it, so 1 of 2 units shows 50% and 2 of 3 shows 66%. That's my inference; TalentLMS doesn't publish the formula. Your indml copies without assignments solve it. So does setting the course to "Completed when: selected units are completed".

कु

How a rebuild would work

Engines plus data, not 300 one-off files

Your 300+ activities are probably built from a dozen or so activity types: conversation dialogue, crossword, word search, join the dots, tracing, colouring, listen and match, picture prepositions, and so on. A rebuild would create one engine per type, and each activity becomes a small data file listing its words, images, audio and correct answers:

{
  "type": "crossword",
  "title": "प्राणी - Animals",
  "level": 1,
  "words": [
    { "answer": "गाय", "clue": "cow.png", "audio": "gaay.mp3" },
    { "answer": "मांजर", "clue": "cat.png", "audio": "manjar.mp3" }
  ]
}

A build step turns each data file into an xAPI (or SCORM 1.2) package for TalentLMS, so tracking keeps working. TalentLMS accepts packages up to 600 MB, so each package can be self-contained.

What AI does well here

  • Writes the engines: touch-friendly, scaling, accessible, and reporting scores to TalentLMS.
  • Handles Marathi correctly, for example splitting words into aksharas (क्ष, ज्ञ) for grids.
  • Reads the old Storyline output (data.js, the slide files) and pulls out the words, answers and media, so you don't retype content.
  • Reuses your existing audio and illustrations directly from the packages.
  • Generates new activities from a word list once the engines exist.

What still needs a person

  • Checking every converted activity: correct answers, audio in sync, nothing missing.
  • Re-creating bespoke character animations. Simpler motion is fine; frame-perfect copies take real work.
  • Teaching judgment: what to keep, merge or improve.
  • Recording any new audio.

Realistic effort: nobody has published a case study of AI automatically converting Storyline courses. Teams that do this rebuild with AI help, which is what I'm proposing. Building an engine is roughly a few working sessions per activity type. The long pole is checking 300+ activities: at 10–15 minutes each, that's roughly 50–75 hours spread over time. A pilot will turn these guesses into real numbers.

कू

Recommended path

Small steps, each useful on its own
  1. This week

    Patch one activity, test it, then patch the rest. Scaling fixed and the tablet app redirect removed. This helps every current student immediately.

  2. Next

    Pilot: rebuild two activity types, for example the Week 1 conversation and one game such as the crossword. Run them in TalentLMS side by side with the originals, on a laptop, an iPad and a phone, and show them to a few kids and teachers.

  3. If the pilot wins

    Build the indml (self-learner) courses in the new format. You were going to copy every course anyway to remove the assignments. Making those copies modern versions turns one chore into an upgrade, and self-learners arriving from the new website get the best experience.

  4. Over time

    Move the school courses across type by type, as each engine proves itself. The patched Storyline versions keep working meanwhile.
